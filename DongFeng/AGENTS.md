# 项目规则

- 涉及远程机器、SSH、IP、端口、账号、共享目录或跳板机连接时，读取本地 `机器IP.md` 获取准确信息。
- 不在回复、日志或提交中重复暴露 `机器IP.md` 中的明文凭据。
- 每次访问远端前必须重新解析 `机器IP.md`，并确认主机器地址末段为 `42`；第二跳 SSH 建立后还必须核验远端主机身份。任一校验不符立即停止，禁止对其他远端执行命令。
- 若 SSH 连接被禁止或被网络策略拒绝，停止连续重试，等待 5 分钟后再进行一次受控重试。
- 所有训练、基线测试、A/B 测试和 profiler 训练必须且只能在完整名称为 `mapqr-leicheng` 的现有容器中执行；禁止在宿主机或 `mapqr`、`mapqr-leicheng-shm64m`、`mapqr-leicheng-incomplete` 等其他容器中训练。
- 所有正式训练与测试必须使用 8 张昇腾 NPU，禁止使用 GPU/CUDA 或 CPU 代替训练。每次启动均需核验 `torch_npu`、8 个分布式 rank 和 `npu-smi` 进程；旧 MMCV 命令行中的 `--gpus 8` 仅是兼容参数名，不能作为设备类型证据。
- 禁止升级、降级、替换或强行改变客户环境中已经存在的驱动、固件、CANN、PyTorch、torch_npu 和项目依赖版本。候选方案若要求改变版本，只记录为不适用，不安装、不试跑。
- 后续优化若本地 Codex 工作机缺少必要软件、工具或依赖，可直接安装并记录用途、版本、来源与验证结果，无需逐项等待确认；此授权不适用于远端客户机器及其容器，远端环境仍遵守禁止安装和变更既有组件的规则。
- 所有优化按可独立验证、可独立回退的功能提交到目标 Git 仓库：同一个算子或同一个完整功能原则上只形成一个 commit，不拆成多个零碎 commit；仅当功能复杂且子能力可独立验证时才允许拆分，并须事先在计划和操作记录中说明边界。性能提交信息统一使用 `【npu性能优化】<具体对象与动作>`。
- 禁止把远端服务器上的数据、日志、profile、数据集、模型、权重、checkpoint 或其他产物拉取到本地；分析必须在远端原位完成，本地只记录脱敏统计摘要。
- profiling 原始数据只允许在远端本轮诊断目录内临时保留；完成原位分析、生成脱敏摘要与校验信息且后续不再需要后，必须立即精确删除，并复核原始 profiling 文件与目录数量为 0。不得误删仍用于当前验收、恢复或评测的训练日志与 checkpoint。
- 每一步操作都必须记录到 `操作步骤.md`，包括目的、原因、操作指令、观察现象、现象说明和下一步。
