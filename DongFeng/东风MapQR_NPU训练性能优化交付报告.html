东风 MapQR / MV2DFusion 昇腾 NPU 训练性能优化交付报告

1. 项目介绍

1.1 概述

面向东风 L2.9 感知训练任务（MapQR / MV2DFusion，SOAP 优化器）在昇腾 NPU 上的训练性能进行系统优化，覆盖 SOAP 预条件器路径、DrivingSDK MSDA、DataLoader / pin_memory、Host 调度与分配器配置等，并在固定客户软件栈下完成 8 卡正式吞吐验收。

1.2 目标

需达到 NPU 8 卡 / GPU 8 卡 = 1:1 的 throughput (samples/s) 性能目标（同 batch / 同 rank 合同下）。

2. 环境依赖

项目 NPU 环境 GPU 对照环境
模型 MapQR / MV2DFusion（SOAP） MapQR / MV2DFusion（SOAP）
硬件平台 Ascend NPU（逻辑设备 8～15，物理后 8 卡） NVIDIA A800 GPU × 8
软件栈 PyTorch 2.7.1、torch_npu 2.7.1、CANN 8.3.RC1 客户 GPU 训练栈（日志对照）；CUDA 环境以客户侧为准
训练方式 DDP，8 rank，batch/rank=16，global batch=128，workers=8，prefetch=3，AMP DDP，8 rank；吞吐按 global batch=128 口径换算

统计口径 正式 876-step 训练窗；profiler-off；关闭测试/调试干扰项 同窗口 1～876 步日志对比（数据集规模/随机语义不完全相同，作跨硬件参照）

资源口径说明：正式验收固定使用后 8 张昇腾 NPU、8 个分布式 rank；旧命令行中的 --gpus 8 仅为兼容参数名，不代表 GPU 训练。

3. 优化效果

3.1 单机优化

阶段 训练资源 876-step 平均 step time / 吞吐
优化前（历史采用点 f922c38） 8 卡 NPU 8.166 s / 15.675 samples/s
优化后（现行 fa95a2a + SOAP_STALE_Q_K=4） 8 卡 NPU 4.776 s / 26.803 samples/s

相对优化前：平均 step time 下降约 41.5%，吞吐提升约 1.71×（+70.9%）。

现行启用合同：export SOAP_STALE_Q_K=4；tools/ddp_train.sh 默认 PYTORCH_NPU_ALLOC_CONF=expandable_segments:True；配置 pin_memory=True（DataContainer 已补齐生效）。默认 SOAP_STALE_Q_K=0 为同步回退。

4. 扩展验证（正确性 / 门禁）

验证项 范围 / 合同 结论
正式 876-step profiler-off；8 rank；后 8 卡；现行优化版本 + k=4 exit 0；876/876；loss 全有限；fatal/OOM/HCCL=0
SOAP stale-Q Stage A～D（含 300-step）后提交 2846401 门禁通过；默认 k=0 可同步回退
pin_memory 100-step e2e 后提交 2a2aa0f 吞吐 PASS；峰值显存基本持平
expandable_segments 30-step A/B 后提交 fa95a2a 吞吐 +1.73%，peak −144 MiB
DrivingSDK MSDA（历史） 相对父提交 876-step / checkpoint / resume / 512-sample 推理 无 loss 数量级偏离；主任务指标无显著恶化
显存 正式 876 峰值 NPU 26201 MiB；GPU 对照窗峰值 28816 MiB

结论：本交付范围为单机 8 卡训练性能优化与验收，未开展双机扩展；在现有门禁下训练过程稳定、loss 有限，未观察到精度崩坏迹象。完整测试集 canonical 评测因环境缺少 ortools（不改变客户既有依赖）尚未补齐，最终业务指标仍以客户评测环境结果为准。

说明：grad_norm 在 NPU 正式 876 中 step3 出现一次 inf（与历史早期 overflow / skip 相位同类）；GPU 对照窗同样存在早期非有限 grad 打印，不作为吞吐对比否决项。
